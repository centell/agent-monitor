## 3줄 요약

세션을 여러 개 띄우면 무엇이 끝나 사람을 기다리는지 알 길이 없어 창을 하나씩 돌며 확인해야 했음.
Claude Code 가 스스로 기록해 두는 세션 레지스트리를 읽어, 메뉴바에는 숫자만 두고 패널에는 접힘 없는 평면 목록을 둠.
레지스트리가 공개되지 않은 형식이라 폴백 경로가 필요하고, 제품 이름과 배포 여부는 아직 정하지 못했음.

## 0. 왜 — 상태를 추측하지 않고 적혀 있는 것을 읽음

세션을 여러 개 띄우는 사용자는 창을 하나씩 돌며 끝났는지 확인하고 있음. 이 도구가 답해야 할 물음은 「무엇을 하고 있나」가 아니라 **「무엇이 끝나서 나를 기다리나」** 임.

- `○` 그 물음의 답은 **추측이 아니라 사실이어야 함**
- `⚠` 파일 변경 시각으로 상태를 추정하면 「긴 명령 실행」과 「승인 대기」가 원리적으로 갈리지 않음
- `○` Claude Code 가 자기 상태를 파일에 적고 있으므로 그것을 읽으면 추측할 일이 없음

이 자리를 노린 도구들에 대한 조사와 측정은 비공개 논거 파일에 둠.

## 1. 지금 — 상태를 적은 파일이 이미 있으나 아무도 읽지 않음

Claude Code 는 세션마다 자기 상태를 파일에 적고 있음. 관측 시점에 실행 중이던 세션 전부가 계정 루트별로 빠짐없이 등록되어 있었음.

- `○` 레지스트리 경로는 계정 루트 아래 `sessions/<pid>.json` 임
- `○` 담긴 항목은 `status` · `name` · `cwd` · `sessionId` · `statusUpdatedAt` 임
- `○` 계정 루트는 `~/.claude` 와 `~/.claude-accounts/*/` 로 여러 개일 수 있음
- `⚠` 공개 문서가 없는 내부 형식이며 Claude Code 2.1.263 에서 관측한 것임

## 2. 상태 — 네 값을 해석하지 않고 그대로 씀

레지스트리가 적어 둔 값을 그대로 화면에 옮김. 파생 판정을 만들지 않는 것이 이 설계의 핵심임.

| `status` | 화면 표기 | 손이 필요한가 |
|---|---|---|
| `waiting` | 승인 대기 | 필요함 |
| `idle` | 입력 대기 | 필요함 |
| `busy` | 작업 중 | 필요 없음 |
| `shell` | 셸 실행 중 | 필요 없음 |

`⚠` `waiting` 과 `shell` 의 정확한 의미는 관측으로만 알고 있어 구현 중 확정할 것임.

- `○` 처음 보는 `status` 값은 임의로 뭉개지 않고 원문 그대로 표시함
- `○` 레지스트리에 있으나 프로세스가 없는 항목은 목록에서 제외함

## 3. 화면 — 메뉴바는 숫자 하나, 패널은 접힘 없는 한 화면

기존 도구의 불편이 두 가지로 좁혀졌으므로 그 반대로 감. 메뉴바가 길어지지 않을 것과, 패널을 열었을 때 더 누를 것이 없을 것이 요구사항임.

- `○` 메뉴바 제목은 `대기중/전체` 꼴의 숫자만 둠
- `○` 세션이 몇 개든 잘라내지 않으며 개수 상한을 두지 않음
- `○` 대기중이 0이면 강조하지 않고, 1 이상이면 눈에 띄게 함
- `○` 패널은 세션당 한 줄이며 접기·펼치기·폴더 계층을 두지 않음
- `○` 목록 정렬은 손이 필요한 것을 위에 두고 그 안에서 오래 기다린 순임
- `○` 한 줄에 담는 것은 상태 · 세션 이름 · 현재 도구 · 경과 시간임
- `○` 줄을 누르면 그 세션이 도는 터미널 창으로 화면을 옮김
- `⚠` 터미널을 찾을 수 없는 세션은 누를 수 없게 두어 생김새로 구분함

```
2/5                                  ← 메뉴바

⏳ payments-api     승인 대기   Bash    2m
○  docs-site       입력 대기   —      20m
●  tools-91         작업 중     Read    4s
◐  web-client-16   셸 실행 중  Bash   31s
```

## 4. 수집 — 레지스트리가 먼저이고 transcript 는 폴백임

두 경로를 함께 두되 우선순위를 고정함. 폴백으로 내려간 사실을 사용자에게 숨기지 않는 것이 조건임.

- `○` 계정 루트를 전부 열거해 각 루트의 `sessions/*.json` 을 읽음
- `○` `ps` 로 프로세스 생존을 확인해 죽은 등록부를 버림
- `○` 현재 도구 이름은 transcript 끝부분만 되감아 읽어 보강함
- `○` 레지스트리를 읽지 못하면 transcript 추측으로 내려가되 화면에 추정치임을 표시함
- `⚠` transcript 는 수십 MB 까지 커지므로 전체를 읽지 않음

## 5. 구조 — 어댑터를 두어 나중 것을 받을 자리를 비워 둠

지금은 Claude Code 하나만 다루나 구현체를 갈아 끼울 수 있게 함. 사용량·시스템 지표도 나중에 들어올 자리를 미리 정해 둠.

- `○` `SessionSource` 프로토콜을 두고 Claude Code 구현체 하나로 시작함
- `○` 패널 한 줄에 지표 칸을 덧붙일 수 있게 행 모델을 열어 둠
- `⏸` Codex·Gemini 구현체는 이번에 만들지 않음
- `⏸` 메모리·CPU 지표는 이번에 넣지 않으나 자리는 남김

`⚠` 확장 지점을 남기는 것과 지금 만드는 것을 섞지 않음.

## 6. 안 하는 것 — v0.1 의 경계

경계를 적어 두지 않으면 검토 중에 범위가 부풀어 오름. 아래는 필요 없다는 뜻이 아니라 이번이 아니라는 뜻임.

- `⏸` 비용 · 토큰 · 사용량 · 할당량 표시
- `⏸` 클립보드 기록 · 마스코트 · 시스템 전반 모니터링
- `⏸` 세션이 끝났을 때 자동으로 그 창으로 데려가는 것
- `⏸` 완료 알림 배너
- `⏸` 로그인 시 자동 실행 등록
- `⏸` 배포에 필요한 라이선스 · 코드 서명 · 공증 · Homebrew tap

## 7. 고른 안과 기각한 안

대안을 함께 적지 않으면 통보문이 됨. 기각 사유의 근거는 논거 파일에 둠.

|---|---|
| 레지스트리를 읽음 | `○` 채택 |

## 8. 검증 — 존재 이유를 한 장면으로 증명함

만든 뒤에 「잘 된다」고 말하지 않고, 어긋나는 순간을 잡아 근거로 남김.

- `○` `--json` 출력을 같은 시각의 레지스트리와 대조함
- `○` Bash 승인 프롬프트를 일부러 띄워 두 도구를 나란히 찍음
- `○` 세션을 6개 이상 띄워 잘림 없이 전부 나오는지 확인함
