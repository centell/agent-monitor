## 3줄 요약

재부팅하면 세션 프로세스가 모두 죽고, 다시 켠 뒤 어느 폴더에서 어느 세션을 열었는지 사람이 기억해서 하나씩 `--resume` 해야 했음.
끄기 전 「세션 저장하고 모두 닫기…」로 목록을 저장하고 세션을 닫음 (못 누른 경우에 대비해 계속 적기도 함). 켠 뒤 메뉴 한 줄로 같은 폴더·같은 계정·같은 옵션의 `claude --resume <id>` 를 Terminal.app 창에 다시 띄우는 것으로 풂.
권한 모드는 `--resume` 이 스스로 되살리는 것을 재 봤으나, 세션을 끄는 신호·종료 알림 순서·백그라운드 세션·codex 옵션은 아직 재지 못했음.

## 0. 왜 — 재부팅 한 번에 세션 일곱 개를 손으로 다시 열어야 했음

주인님 말씀: 「이대로 재부팅하고 켜도 지금 켜둔 세션들이 다 유지되도록」.

2026-11-14 이 맥에는 터미널 Claude 세션이 일곱 개 떠 있었고, 그중 둘은 다른 계정(`~/.claude-accounts/rmcentell`)이었음. 재부팅하면 일곱 개의 폴더·세션 id·계정·`--remote-control` 이름을 사람이 기억해 되살려야 함.

- `○` 이 문서가 답할 물음은 **「켠 뒤 한 번 눌러서 끄기 전과 같은 세션 목록으로 돌아갈 수 있나」** 임
- `⚠` 돌아오지 않는 것이 있음 (5절). 「유지」라고 부르지 않음

## 1. 지금 — 다시 열 재료는 이미 다 읽히고 있음

`ClaudeCodeSource` 가 훑을 때 이미 세션 id·작업 폴더·계정 루트·`kind`(interactive/bg)·이어진 세션 고리를 갖고 있음. 창은 `TerminalJump` 가 tty 로, tmux 는 `Tmux` 가 pane 으로 찾음. 새로 읽어야 할 것은 **프로세스 인자** 하나뿐임.

| 다시 열 때 필요한 것 | 어디서 오나 | 상태 |
|---|---|---|
| 세션 id | 레지스트리 `sessionId` | `○` 이미 읽음 |
| 작업 폴더 | 레지스트리 `cwd` | `○` 이미 읽음 |
| 계정 | 레지스트리가 있던 루트 (`Session.accountRoot`) | `○` 이미 읽음 |
| 백그라운드인가 | 레지스트리 `kind == "bg"` | `○` 이미 읽음 |
| 띄울 때의 옵션 | 프로세스 인자 (`KERN_PROCARGS2`) | `△` 새로 읽어야 함. 같은 사용자 프로세스라 읽힘 (실측 `ps`) |
| tmux 세션 이름 | `Tmux` 의 pane 조회 | `○` 이미 읽음 |
| codex 세션 id | rollout 파일 이름의 uuid | `○` 이미 읽음 |

## 2. 언제 적나 — 계속 적고, 「끝난 것」과 「끊긴 것」을 시각으로 가름

### 2.1 단추·종료 알림에만 기대지 않음

- `○` 주 경로는 「세션 저장하고 모두 닫기…」 (4.0). 누르는 순간 저장하므로 종료 순서에 흔들리지 않음
- 아래는 그 단추를 못 누른 경우의 대비임
- 단추 방식은 갑작스러운 꺼짐·커널 패닉·배터리 방전에서 아무것도 안 남음
- macOS 종료 알림(`NSWorkspace.willPowerOffNotification`)은 정상 종료에서만 오고, 그때도 Terminal.app 이 먼저 닫혀 세션이 이미 죽었을 수 있음 `⚠` 순서는 재지 못했음
- `○` 그래서 **훑을 때마다 적음**. 기록이 곧 「마지막으로 본 살아 있던 세션들」임

### 2.2 그냥 덮어쓰면 안 되는 이유

정상 종료 중에는 Terminal.app 이 창을 닫으며 세션이 하나씩 죽음. 그 사이에 훑으면 목록이 줄어든 채로 덮어써져, 켠 뒤에는 0개가 남을 수 있음.

- `○` 사라진 세션을 바로 지우지 않고 **`lastSeen` 시각과 함께 남겨 둠**
- `○` 켠 뒤 후보 = 기록의 마지막 쓰기 시각에서 **몇 분 안에** 아직 보였던 세션
  - 재부팅 몇 시간 전에 사람이 닫은 세션은 `lastSeen` 이 오래돼 빠짐
  - 종료 직전에 줄줄이 죽은 세션은 마지막 쓰기와 가까워 남음
- `△` 몇 분으로 할지(초안 3분) 구현 때 정함
- `△` 종료 알림을 받으면 그 뒤로는 「사라짐」을 적지 않음 — 있으면 정확도가 오르고, 없어도 위 규칙으로 동작함
- `○` 오래된 항목은 하루 지나면 지움 (기록 파일이 자라지 않게)

### 2.3 「재부팅 뒤」인지 어떻게 아나

- `○` 기록의 마지막 쓰기 시각이 이번 부팅 시각(`sysctl kern.boottime`)보다 앞이면 재부팅 뒤임
- `○` agent-monitor 만 다시 켠 경우에는 세션이 살아 있으므로 아무것도 권하지 않음
- `○` 켠 뒤에 이미 다시 떠 있는 세션 id 는 후보에서 뺌 (손으로 먼저 연 경우)

### 2.4 기록 자리와 모양

`~/Library/Application Support/AgentMonitor/last-sessions.json` (쓰임새 기록 `stats/` 와 같은 폴더).

```json
{
  "writtenAt": "2026-11-14T10:46:55Z",
  "seen": [
    {
      "source": "claude",
      "id": "090a9644-…",
      "name": "da",
      "cwd": "/Users/…/daily-arcade",
      "accountRoot": "/Users/…/.claude",
      "background": false,
      "args": ["--remote-control=daily-arcade"],
      "droppedArgs": [],
      "state": "idle",
      "lastSeen": "2026-11-14T10:46:55Z"
    }
  ],
  "saved": { "at": "…", "byUser": true, "sessions": [ … ] }
}
```

- `○` `seen` 은 계속 적기. `state` 를 함께 적어 「끊길 때 작업 중이었던 세션」을 켠 뒤 표시함
- `○` `saved` 는 다시 열 목록. 「세션 저장하고 모두 닫기…」를 누르면 그 순간의 목록이 `byUser: true` 로 들어감. 재부팅을 알아채면 `seen` 에서 올린 것이 `byUser: false` 로 들어감
- `○` `saved` 는 다 열리거나(살아 있는 세션 id 와 겹치면 연 것으로 침) 「목록 지우기」를 누를 때까지 남음. 계속 적기는 `saved` 를 덮지 않음
- `○` 재부팅 없이 저장하고 닫기만 해도 「저장한 세션 다시 열기」가 뜸 (정리용으로도 씀)
- `○` 쓰기는 세션이나 상태가 바뀌었을 때, 아니면 30초마다. 원자적으로 씀 (반쯤 쓴 파일이 남지 않게)
- tmux 였다는 표시는 적지 않음 (`⏸`). 새 창으로 열기는 같으므로 메뉴 표시만 빠짐

## 3. 무엇을 다시 붙이나 — 기록이 되살리는 것은 붙이지 않음

### 3.1 실측: `--resume` 이 권한 모드를 되살림

2026-11-14, Claude Code 2.1.325. 이 맥의 기본 권한 모드는 `auto` 임.

1. `claude --session-id <id> --permission-mode plan` 로 띄우고 한 턴 주고받음 → 화면 `⏸ plan mode on`
2. 기록(transcript)에 `{"type":"permission-mode","permissionMode":"plan"}` 줄이 남음
3. 그 프로세스를 `kill -9` 로 끊음 (갑자기 꺼진 경우를 흉내 냄)
4. 옵션 없이 `claude --resume <id>` → 화면 `⏸ plan mode on`

기본값(`auto`)이 아니라 plan 으로 돌아왔으므로, 권한 모드는 **기록에서** 되살아남.

- `○` `--permission-mode` 는 다시 붙이지 않음. 붙이면 세션 중간에 shift+tab 으로 바꾼 모드를 처음 모드로 되돌려 버림
- `△` 모델도 기록을 따르는 것으로 보였음 (설정 기본값 `opus` 가 아니라 기록의 마지막 모델로 열림). 다만 시험에서 `--model haiku` 를 줬는데 기록에는 sonnet 이 답한 것으로 남아 있어, 「띄울 때의 `--model`」이 되살아나는지는 깨끗이 가려지지 않음. 그래서 `--model` 도 붙이지 않는 쪽으로 두고, 구현 전에 한 번 더 잼

### 3.2 다시 붙이는 것 — 허용 목록

| 옵션 | 붙이나 | 까닭 |
|---|---|---|
| `--remote-control[=이름]` | `○` 붙임 | 이 맥의 세션 일곱 중 여섯이 이걸로 떠 있음. 기록이 되살리는지는 못 가렸음 (설정 기본값이 켜져 있어 구분이 안 됨) — 붙여도 해가 없음 |
| `--add-dir` | `○` 붙임 | 폴더 권한이라 기록에 없음 |
| `--dangerously-skip-permissions` · `--allow-dangerously-skip-permissions` | `○` 붙임 | 사람이 고른 위험 설정이라 빠지면 조용히 달라짐 |
| `--permission-mode` · `--model` | `○` 안 붙임 | 기록이 되살림 (3.1) |
| `--session-id` · `--resume` · `-c` · `--fork-session` | `○` 안 붙임 | 다시 열기가 스스로 정함 |
| `-p` · 위치 인자(첫 프롬프트) | `○` 안 붙임 | 첫 프롬프트를 다시 보내면 안 됨 |
| 그 밖의 처음 보는 옵션 | `○` 안 붙이고 `droppedArgs` 에 적음 | 메뉴에 「안 붙인 옵션: …」으로 보임. 조용히 버리지 않음 |

### 3.3 계정

- `○` 계정 루트가 `~/.claude` 가 아니면 `CLAUDE_CONFIG_DIR=<루트>` 를 붙여 엶
- 프로세스 환경에서도 같은 값이 읽힘을 확인했음 (`ps eww` → `CLAUDE_CONFIG_DIR=…/rmcentell`). 하지만 레지스트리 위치가 이미 같은 답을 주므로 환경을 읽지 않음

## 4. 어떻게 여나

### 4.0 「세션 저장하고 모두 닫기…」

- `○` 누르면 지금 목록을 바로 저장함 (2.4 의 기록에 「사람이 저장함」 표시)
- `○` 확인 창: 닫을 세션 N개, 그중 작업 중인 세션 목록 → 「끝날 때까지 기다렸다 닫기 / 지금 모두 닫기 / 취소」
- `○` 기다리는 동안 메뉴 줄에 「닫기 대기 중 · 작업 중 N개」를 보이고, 다 쉬면 닫음
- `○` 재부팅 자체는 사람이 함. agent-monitor 는 재부팅을 걸지 않음
- `○` 대화형 세션은 SIGTERM 으로 끔. 백그라운드 세션은 지금 있는 `claude stop <id>` (SessionStop) 를 씀
  - 실측 (2026-11-14, claude 2.1.325, haiku 시험 세션): 쉬는 중·셸 도는 중·응답 쓰는 중 셋 다 SIGTERM 4초 안에 내려감. 레지스트리 파일이 지워지고 기록 끝에 `cost-state`·`last-prompt` 를 적고 나감
  - 응답 쓰는 중에 끄면 **그 응답은 사라지고 보낸 질문은 남음.** 다시 열면 질문이 화면에 보이고 저절로 이어 쓰지는 않음. 돌던 백그라운드 셸은 죽고 「이전 세션이 끝나기 전에 못 끝남」으로 표시됨
  - 그래서 「기다렸다 닫기」가 기본값임
- `△` 프로세스만 끄고 Terminal 창은 남김. 창까지 닫을지는 구현 때 다시 봄
- `△` codex 세션도 같이 닫을지는 codex 실측 뒤 정함

### 4.1 메뉴

- `○` 재부팅 뒤 후보가 있으면 메뉴 맨 위에 한 줄: **「저장한 세션 다시 열기 (N개)」**
- `○` 하위 메뉴에 세션마다 한 줄 (이름 · 폴더 · 끊길 때 작업 중이었으면 표시) + 「모두 열기」
- `○` 상시 띄우기 창에도 같은 한 줄
- `○` 「닫기」를 누르거나 후보가 다 열리면 그 줄은 사라짐

### 4.2 터미널 세션

`TerminalJump` 와 같은 AppleScript 통로로 Terminal.app 에 새 창을 엶.

```applescript
tell application "Terminal" to do script "cd '<cwd>' && CLAUDE_CONFIG_DIR='<root>' claude --resume <id> --remote-control=<이름>"
```

- `○` 경로·이름은 셸 따옴표로 감쌈 (공백·한글 폴더가 실제로 있음 — iCloud 볼트 경로)
- `○` 권한은 창 이동과 같은 자동화 권한 하나임. 새로 묻지 않음
- `⚠` macOS 「다시 로그인할 때 윈도우 다시 열기」가 켜져 있으면 Terminal.app 이 빈 셸 창을 스스로 되살림. 그 창들은 그대로 두고 새 창을 엶 — 빈 창을 닫는 일은 하지 않음
- `△` 창 위치·크기까지 되살리는지는 범위 밖으로 둠 (창 이동 기능도 위치를 다루지 않음)
- `⏸` iTerm2·Ghostty 는 창 이동과 같은 이유로 다루지 않음

### 4.3 백그라운드 세션

- `○` 창 없이 `claude --bg --resume <id>` 를 바로 실행함 (CLI 도움말: 「같은 ID 로 백그라운드에서 이어 감」)
- `○` 실측 (2026-11-14): `claude --bg --resume <id>` 가 같은 id 로 `kind: bg` 세션을 띄움. `/rename` 으로 붙인 이름(`custom-title`)도 돌아옴. 이름을 따로 붙인 적 없는 세션은 폴더 이름 대신 id 앞 8자가 이름이 됨

### 4.4 이어진 세션 (프로세스 둘에 걸친 세션)

세션이 이어지면 대화는 뒤 프로세스로 옮겨 가고 창은 앞 프로세스가 쥠 (`merged` 주석).

- `○` 기록에는 **뒤쪽 세션 id 하나**만 적음. 앞쪽 id 로 열면 넘겨주기 전의 대화로 돌아감
- `○` 옵션은 창을 쥔 앞 프로세스(`hostPid`)의 인자에서 읽음 — 사람이 띄운 쪽이 그쪽임

### 4.5 codex

- `○` `codex resume <uuid>` (CLI 도움말로 확인)
- `⚠` codex 를 띄울 때의 옵션(`-c`·모델·샌드박스)이 기록에서 되살아나는지 재지 못했음. 이 맥에 지금 떠 있는 터미널 codex 가 없었음. 되살리는지 재기 전까지는 옵션을 붙이지 않고 `droppedArgs` 로 보임

## 5. 돌아오지 않는 것

다시 열린 세션은 **대화만** 이어짐. 아래는 사람에게 미리 보임.

- 끊길 때 돌던 턴 — 응답 중간이었으면 그 응답은 없음
- 세션이 띄운 개발 서버·백그라운드 셸·Monitor
- 세션 안에서만 사는 예약 (세션에 묶인 cron 등)
- tmux 서버 자체 (재부팅으로 함께 죽음)
- `△` 작업판 표: 세션 id 가 같으므로 표를 쥔 채로 돌아올 것으로 봄. 재지 않았음
