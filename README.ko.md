# agent-monitor

**어느 세션이 나를 기다리고 있나.**

Claude Code 세션을 여러 개 띄워두고 쓰는 사람을 위한 macOS 메뉴바 앱입니다. 어려운 물음은
*무엇을 하고 있나* 가 아니라 *무엇이 끝나서 나를 기다리나* 입니다. 메뉴바의 숫자 하나와
그 뒤의 평면 목록으로 그 물음에 답합니다.

> 영어 문서는 [README.md](README.md) 에 있습니다.
>
> **한국어·영어를 지원합니다.** 기본값은 맥의 언어를 따르고, 설정에서 직접 고를 수도 있습니다.

---

## 무엇을 보여주나

메뉴바에는 `2/5` — 기다리는 것 둘, 살아있는 것 다섯. 그게 전부입니다. **세션이 몇 개든
제목이 길어지지 않고, 목록을 잘라내지도 않습니다.**

누르면 모든 세션이 한 화면에 들어옵니다. 접힘 없이, 손이 필요한 것이 위로:

```
◆  payments-api     승인 대기   Bash    2m      █▎   RAM  0.6G  CPU   0%
○  docs-site        입력 대기   —      20m      ▊    RAM  0.4G  CPU   0%
──────────────────────────────────────────────────────────────────────
●  web-client       작업 중     Read    4s      █▌   RAM  0.8G  CPU  12%
◐  data-pipeline    셸 실행 중  Bash   31s      █▍   RAM  0.7G  CPU   3%
──────────────────────────────────────────────────────────────────────
메모리 15.6/25.8GB · 스왑 12.3GB · 에이전트 3.7GB
```

| 표식 | 상태 | 손이 필요한가 |
|---|---|---|
| `◆` | `waiting` — 승인 프롬프트가 떠 있음 | **필요** |
| `○` | `idle` — 턴이 끝나 입력을 기다림 | **필요** |
| `●` | `busy` — 생성 중 | 불필요 |
| `◐` | `shell` — 셸 명령 실행 중 | 불필요 |

줄을 누르면 그 세션이 도는 터미널 창이 앞으로 옵니다.

## 왜 만들었나

답할 가치가 있는 물음은 *이 세션이 무엇을 하고 있나* 가 아니라 **멈춰서 나를 기다리고 있나**
입니다. 그 답은 추론이 아니라 사실이어야 하고요.

transcript 파일이 언제 바뀌었는지로 상태를 추측하면, **오래 도는 셸 명령과 승인을 기다리는
프롬프트가 갈리지 않습니다** — 둘 다 조용하니까요. Claude Code 는 자기 상태를 디스크에 적고
있으므로, 그것을 읽고 거기서 아무것도 파생시키지 않습니다.

## 어떻게 재는가

**상태는 추측하지 않고 레지스트리에서 읽습니다.** Claude Code 가
`<계정루트>/sessions/<pid>.json` 에 `status` 를 적습니다. 그 값을 그대로 옮기고 파생 판정을
만들지 않습니다. 처음 보는 값은 뭉개지 않고 원문 그대로 보여줍니다.

- **계정 루트를 전부** 훑습니다 — `~/.claude`, `~/.claude-accounts/*/`, `CLAUDE_CONFIG_DIR`.
  `projects/` 가 링크로 합쳐져 있어도 **레지스트리는 루트마다 따로** 있습니다.
- **생존 확인**은 커널의 프로세스 시작 시각과 레지스트리 `startedAt` 을 맞춰 봅니다. 실행 파일
  이름이나 경로로 판단하지 않습니다 — 설치 방식마다 달라서 남의 환경에서 깨집니다.
- **메모리는 프로세스 트리 전체**입니다. `claude` 하나만 재면 크게 틀립니다. 실측에서 단독
  541MB 였던 세션이 자손 26개까지 합치면 2790MB 였습니다.
- **CPU** 는 순간값을 읽을 수 없어 두 표본의 차이로 구합니다.
- **터미널 이동**은 `tty` 로 세션과 창을 잇습니다.

표본 1회에 **약 12ms** — 기본 2초 주기의 **0.6%** 입니다.

## 설치

Swift 컴파일러(`xcode-select --install`)가 필요합니다. 그 외 의존성은 없습니다.

`build.sh` 는 **유니버설 바이너리**(Apple Silicon + Intel)를 macOS 13 대상으로 만듭니다.
어느 한 아키텍처를 만들 수 없는 환경이면 그것만 건너뛰고 빌드는 계속됩니다.

macOS 13 SDK 로 **컴파일되는 것은 확인했지만, 실제로 돌려 본 것은 macOS 26 뿐입니다.**
옛 판은 지원 범위가 아니라 «확인 못 한 땅»입니다 — 이상하면 이슈로 알려주세요.

```sh
git clone https://github.com/centell/agent-monitor.git
cd agent-monitor
./build.sh
```

`build.sh` 가 컴파일해서 `~/Applications/AgentMonitor.app` 에 설치하고 띄웁니다. 다시 빌드하면
앱을 갈아 끼우고, **돌고 있었으면 알아서 다시 올립니다.** 다시 띄우지 않으려면 `--no-run`.

세션 줄을 처음 누를 때 macOS 가 Terminal 제어 권한을 묻습니다. **허용해야 창이 움직입니다.**

## 쓰는 법

**메뉴바** — 숫자. 누르면 목록. `⌘,` 로 설정.

**설정**은 두 탭입니다:

- **표시** — 언어, 줄 배치, 어떤 칸을 보일지, 지표 상세, 갱신 주기. **살아있는 미리보기**가 실제
  세션을 메뉴와 같은 코드로 그리므로, 보이는 그대로가 결과입니다.
- **메모리** — 시스템 사용/스왑/압축, 에이전트 합계, 세션 트리 밖에서 가장 많이 쓰는 것들.
  작업 폴더가 세션 폴더 아래인 프로세스는 **«띄운 것으로 보이는 것»** 으로 따로 묶고 세션
  합계에는 넣지 않습니다.

**명령줄** — 같은 데이터를 GUI 없이:

```sh
agent-monitor --list      # 사람이 읽는 표
agent-monitor --json      # 기계가 읽는 형식
agent-monitor --memory    # 이 맥의 메모리를 누가 쓰는지
agent-monitor --roots     # 훑는 계정 루트
```

## 한계

- **레지스트리는 문서화되지 않은 내부 파일입니다.** Claude Code 2.1.263 에서 관측했습니다.
  형식이 바뀌면 깨집니다. transcript 기반 폴백이 있고, 폴백으로 내려가면 **조용히 틀리는 대신
  「추정치」라고 화면에 적습니다.**
- **Terminal.app 만** 됩니다. iTerm2·Ghostty·WezTerm·kitty 는 각자 다른 자동화 통로가 필요합니다.
  tmux 안에서는 창까지만 가고 패널까지는 못 갑니다.
- **세션이 띄운 서버가 합계에서 빠질 수 있습니다.** 개발 서버나 컨테이너가 세션 프로세스 트리에서
  떨어져 나가면 그 세션 합계에 안 잡힙니다. 메모리 탭이 그걸 드러내지만 **귀속은 작업 폴더로
  미루어 본 추정**이고, 한 프로젝트에 세션이 여럿이면 하나를 고르지 않고 「여러 세션 (n)」이라고
  적습니다.
- **서명이 없습니다.** 로컬 빌드이고 공증된 릴리스는 아직 없습니다.
- **macOS 전용**이고 아직 Claude Code 만 압니다. 다른 CLI 는 `SessionSource` 자리에 붙습니다.

  한쪽만 고치면 눈에 띕니다. 언어를 더하려면 그 파일을 넓히면 됩니다.
- 주석은 한국어이고 좀 깁니다. **왜 그렇게 했는지**를 담고 있고, 뒤집힌 결정도 함께 적혀 있습니다.
  지우기보다 그 습관을 이어주시면 좋겠습니다.
- 이 저장소의 주장은 **재본 것**이지 짐작이 아닙니다. 숫자를 적으면 어떻게 얻었는지 함께 적고,
  재지 못했으면 재지 못했다고 적어주세요.
