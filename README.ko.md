# agent-monitor

**어느 세션이 나를 기다리고 있나.**

Claude Code 세션을 여러 개 띄워두고 쓰는 사람을 위한 macOS 메뉴바 앱입니다. 어려운 물음은
*무엇을 하고 있나* 가 아니라 **무엇이 끝나서 나를 기다리나** 입니다.

English: [README.md](README.md)

---

## 무엇을 보여주나

메뉴바에는 `2/5` — 기다리는 것 둘, 살아있는 것 다섯. 그게 전부입니다. **세션이 몇 개든
제목이 길어지지 않고, 목록을 잘라내지도 않습니다.**

누르면 모든 세션이 한 화면에 들어옵니다. 접힘 없이, 손이 필요한 것이 위로:

```
◆  payments-api     승인 대기   Bash    2m      █▎   RAM  0.6G  CPU   0%
○  docs-site        입력 대기   —      20m      ▊    RAM  0.4G  CPU   0%
──────────────────────────────────────────────────────────────────────
●  web-client       작업 중     Read    4s      █▌   RAM  0.8G  CPU  12%
◐  data-pipeline    셸 실행 중  Bash   31s      █▍   RAM  0.7G  CPU   3%
──────────────────────────────────────────────────────────────────────
메모리 15.6/25.8GB · 스왑 12.3GB
에이전트 3.7GB
```

| 표식 | 상태 | 손이 필요한가 |
|---|---|---|
| `◆` | `waiting` — 승인 프롬프트가 떠 있음 | **필요** |
| `○` | `idle` — 턴이 끝나 입력을 기다림 | **필요** |
| `●` | `busy` — 생성 중 | 불필요 |
| `◐` | `shell` — 셸 명령 실행 중 | 불필요 |

상태는 **Claude Code 가 자기 자신을 위해 적어 두는 파일**에서 읽습니다. 파일 변경 시각으로
추측하지 않으므로 **승인 대기와 오래 도는 셸 명령이 갈립니다** — 추측하면 둘 다 그냥 조용해 보입니다.

손이 필요한 줄에 **마우스를 올리면 왜 기다리는지**가 나옵니다. 승인 대기는 기다리고 있는
호출을(`Bash: pnpm build --filter web`), 입력 대기는 마지막으로 건넨 말을 보여줍니다
(`커밋할까요, 아니면 검수까지 두고 갈까요?`). 도는 중인 줄은 아무 말도 안 합니다 — 아직
답할 것이 없으니까요.

**줄이 아니라 마우스 올림에 둔 것은 일부러입니다.** 줄에 두면 할 말이 없는 «작업 중» 줄까지
폭을 물어야 했고, 정작 이유가 있는 줄은 폭에 맞춰 잘려 **물음의 끝** — 무엇을 고르라는지 —
이 사라졌습니다. 올려 보면 폭도 안 들고 잘리지도 않습니다. 이 값은 앱이 이미 읽고 있던
기록에서 꺼내므로 새로 하는 일이 없고, 못 찾으면 추측 대신 아무것도 안 냅니다.
명령이 화면에 뜨는 게 싫으시면 «표시» 에서 끄시면 되고, `--json` 에는 `reason` 으로 나옵니다.

줄을 누르면 그 세션이 도는 터미널 창이 앞으로 옵니다.

줄을 **우클릭하면 고정**됩니다. 고정한 세션은 손을 기다리는 동안 다른 것들보다 위로 올라오고
바탕이 옅게 깔립니다. 도는 중일 때는 자리를 지킵니다 — 아직 손댈 일이 없으니까요.
핀은 그 세션과 함께 삽니다. 세션을 껐다 켜면 다시 꽂으시면 됩니다.

## 설치

### 빌드 받기

[Releases](https://github.com/centell/agent-monitor/releases) 에 유니버설 앱이 올라가 있습니다.

> **서명도 공증도 없습니다.** 배포용 서명에는 유료 Apple Developer 계정이 필요한데 이 프로젝트에는
> 없습니다. 그래서 macOS 가 **처음 한 번은 열기를 거부합니다.**

1. 압축을 풀고 `AgentMonitor.app` 을 앱 두시는 곳에 옮깁니다
2. **앱을 우클릭 → 열기**, 대화상자에서 확인
3. 그래도 거부되면: 시스템 설정 → 개인정보 보호 및 보안 → 아래로 내려 **「그래도 열기」**

한 번이면 됩니다. 이후 실행은 평범합니다. 직접 빌드하셔도 됩니다 — 명령 두 줄, 15초쯤입니다.

### 소스로 빌드

Swift 컴파일러(`xcode-select --install`)가 필요합니다. 그 외 의존성은 없습니다.

```sh
git clone https://github.com/centell/agent-monitor.git
cd agent-monitor
./build.sh
```

`build.sh` 가 컴파일해서 `~/Applications/AgentMonitor.app` 에 설치하고 띄웁니다. 다시 빌드하면
앱을 갈아 끼우고, **돌고 있었으면 알아서 다시 올립니다.** 다시 띄우지 않으려면 `--no-run`.

세션 줄을 처음 누를 때 macOS 가 Terminal 제어 권한을 묻습니다. **허용해야 창이 움직입니다.**

## 쓰는 법

**메뉴바** — 숫자. 누르면 목록. `⌘,` 로 설정.

**설정**은 두 탭입니다:

- **표시** — 언어, 줄 배치, 어떤 칸을 보일지, 마우스를 올렸을 때 왜 기다리는지 보일지,
  지표 셋(RAM 막대 · RAM GB · CPU %)을 각각 켜고 끄기,
  갱신 주기. **살아있는 미리보기**가 실제 세션을 메뉴와 같은 코드로 그리므로, 보이는 그대로가
  결과입니다.
- **메모리** — 시스템 사용/스왑/압축, 에이전트 합계, 세션 트리 밖에서 가장 많이 쓰는 것들.
  세션별 메모리는 `claude` 하나가 아니라 **프로세스 트리 전체**를 합친 값이며, 보통 몇 배 큽니다.

**명령줄** — 같은 데이터를 GUI 없이:

```sh
agent-monitor --list      # 사람이 읽는 표
agent-monitor --json      # 기계가 읽는 형식
agent-monitor --memory    # 이 맥의 메모리를 누가 쓰는지
agent-monitor --roots     # 훑는 계정 루트
agent-monitor --stats     # 실제로 어떻게 써 왔는지 (7일치, `--stats 30` 이면 한 달)
```

한국어와 영어를 지원하며, 기본값은 시스템 언어를 따릅니다.

## 세션을 몇 개까지 감당하시나요

세션을 늘리는 것은 **따라갈 수 있는 동안만** 이득입니다. 세션은 사람을 기다리는 동안 아무것도
만들지 않고, 사람은 한 명입니다. 그래서 줄이 이미 서 있다면 하나 더 띄워도 대부분 램만 늡니다.
이 앱은 그 줄을 몇 초마다 이미 재고 있으므로, 그걸 쌓아 둡니다.

```
$ agent-monitor --stats
최근 7일 — 기록 4일치 · 앞에 계셨던 시간 21.6시간

  세션 수           평균 4.2 · 최대 7
  실제로 돌던 수    평균 1.6
  대기 줄 길이      없음 12% · 하나 47% · 둘 이상 41%
  대기 시간         중앙값 3분 12초 · 최장 41분 · 합계 3시간 42분  (44번)
  에이전트 램       평균 3.1GB · 최대 5.4GB · 스왑 평균 12.3GB
```

줄서기로 읽으시면 됩니다. **둘 이상**이 밀리고 있던 시간이고, **없음**이 손이 비어 있던
시간입니다. 위 숫자는 줄이 선 시간이 손이 빈 시간의 세 배라는 뜻입니다.

모든 값은 **앞에 계셨던 시간**만 셉니다. 마지막 입력 시각으로 가르는데, 이 구분이 없으면
하룻밤 자는 동안 세션 다섯이 전부 대기로 앉아 「다섯 줄이 밀림」이 되고 매일이 똑같이 보입니다.
남는 것은 개수·시간·메모리뿐이며 **대화 내용은 남지 않습니다.** «표시» 에서 끌 수 있고, 파일은
`~/Library/Application Support/AgentMonitor/stats/` 에 하루 한 개씩 CSV 로 30일간 있습니다.

「N개가 적당합니다」 같은 문장은 **일부러 아직 없습니다.** 그 문턱은 쌓인 날들에서 나와야지,
아무 날도 쌓이기 전에 지어낸 것이면 통계가 아니라 상상입니다.

## 한계

- **세션 상태는 문서화되지 않은 내부 파일에서 옵니다.** Claude Code 2.1.263 에서 관측했습니다.
  형식이 바뀌면 깨집니다. transcript 를 읽는 폴백이 있고, 그때는 **조용히 틀리는 대신 「추정치」로
  표시**합니다.
- **터미널 이동은 Terminal.app 만** 됩니다. iTerm2·Ghostty·WezTerm·kitty 는 각자 다른 자동화
  통로가 필요하고, tmux 안에서는 창까지만 가고 패널까지는 못 갑니다.
- **세션이 띄운 서버가 그 세션 합계에서 빠질 수 있습니다.** 프로세스 트리에서 떨어져 나간 개발
  서버나 컨테이너는 안 잡힙니다. 메모리 탭이 따로 보여주며, 한 프로젝트에 세션이 여럿이면 하나를
  고르지 않고 「여러 세션 (n)」이라고 적습니다.
- **서명이 없습니다.** 릴리스도 서명·공증이 없어 macOS 가 첫 실행을 막습니다.
- **macOS 전용**이고 유니버설(Apple Silicon + Intel)입니다. macOS 13 SDK 로 빌드하지만 실제로
  돌려 본 것은 macOS 26 뿐이며, 아직 Claude Code 만 압니다.
